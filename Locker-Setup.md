# Locker setup

1. Stop Play Mode. Create a locker root in the scene and add NetworkObject and LockerHiding. Keep the root active. Put the visible locker mesh under it.
2. Add a non-trigger collider to the locker interaction surface and set that collider object's layer to Interactable. Existing PlayerInteraction handles holding E and the InteractionHUD text.
3. Create three empty child transforms: Inside (player feet inside), View (eyes inside, forward points out), Exit (safe player feet outside). Assign them to LockerHiding. Keep Exit clear of the door, walls and other colliders; allow room for the player's capsule. Use unit scale for the root/anchors.
4. On the existing player Animator controller, add Base Layer states LockerEnter, LockerHidden and LockerExit with your animation clips. Disable root motion in the clips: movement is supplied by the owning player's existing network transform. LockerHidden should loop. Set the component's state path fields to match. No automatic asset installer is used.
5. Match Enter Duration and Exit Duration to the clips. Return State defaults to Base Layer.Idle Walk Run Blend; change it if your controller differs. Remote players see these states; the occupant gets camera movement and roll instead.
6. A scene-placed locker needs no dynamic prefab registration. If spawning lockers dynamically later, register its prefab in the existing NetworkManager configuration and spawn on the server.

## Test with Host and Client

Assign Door Pivot to the actual hinge transform (only the door mesh/collider should be its children). Local X/Y are preserved; Door Open Z defaults to -140 and Door Closed Z to 0. Entry/exit opens the door before player presentation and keeps it open until the configured duration ends. Hidden/Empty closes it. This uses synchronized locker phases on every peer, including late joiners. Do not animate or NetworkTransform-drive the same door pivot from another component. These are immediate rotations, not a separate door-opening animation. Match entry/exit durations to the character clips.

- Hold E on the same locker simultaneously: only one enters, the other sees '이미 누가 있는 듯 하다'.
- Release E after entering; press E again to leave. Occupancy remains locked through the entire exit duration.
- Swap roles and repeat. Check camera restoration, movement, item camera C, and interaction after exit.
- Disconnect or kill the occupant: the server releases the locker. Scene unload restores local input.
- The shared NetworkMonsterPlayerTargetResolver ignores Hidden occupants. Entering/Exiting are still targetable. Monster-specific searches bypassing that resolver, noise investigation, and attack hitboxes are not granted automatic immunity.

Locker geometry, door animation, custom character animation clips, and safe exit placement are authored in Unity. No door rig or animation assets are generated by this component.
